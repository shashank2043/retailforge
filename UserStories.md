This document details the Agile User Stories and system-level requirements for the **Smart Retail Billing & Inventory System**. These user stories define the deliverables and acceptance criteria for our microservices backend.

---

## 📋 User Stories Table

| Story ID | Service | User Story | Acceptance Criteria | Priority | Dependencies |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **AUTH-101** | Auth Service | As an Administrator, I want to register and onboard Cashiers and Store Managers in Keycloak so that they can access the retail platform with appropriate pre-configured access levels. | • Registration creates user accounts in Keycloak with unique username, email, password, and designated role.<br>• Only users with the `ADMIN` role defined in Keycloak can register new users. | High | API Gateway |
| **AUTH-102** | Auth Service | As a Cashier / Store Manager / Admin, I want to authenticate against Keycloak using my credentials so that I can obtain a secure JWT session token to perform authorized operations. | • Valid credentials return a Keycloak-issued and signed JWT token containing the assigned roles (`ADMIN`, `CASHIER`, `STORE_MANAGER`).<br>• Authentication and authorization (RBAC) are verified and enforced via the Keycloak JWT token.<br>• Invalid credentials return HTTP 401 Unauthorized. | High | API Gateway |
| **AUTH-103** | Auth Service | As a logged-in user, I want to refresh my expired access token using a refresh token so that my session is not interrupted while working. | • A valid refresh token returns a new access token and updated refresh token.<br>• Expired or revoked refresh tokens force the user to re-authenticate. | Medium | - |
| **PROD-201** | Product Service | As an Admin / Store Manager, I want to add new products to the catalog so that they are available for inventory tracking and POS billing. | • Required fields include unique Barcode, Name, Price, and GST Percentage.<br>• Newly added products are instantly cached in Redis for high-speed POS retrieval. | High | Auth Service |
| **PROD-202** | Product Service | As an Admin / Store Manager, I want to update or delete product details so that sales and tax calculations are accurate. | • Updates to product details must invalidate/update the corresponding Redis cache entry.<br>• Triggers a `PRODUCT_UPDATED` Kafka event to synchronize details across services. | High | Auth Service |
| **PROD-203** | Product Service | As a Cashier, I want to retrieve product details by scanning/submitting a barcode so that billing can be performed quickly. | • System attempts barcode lookup in Redis cache first for sub-50ms latency.<br>• If a cache miss occurs, the system queries MySQL, populates the Redis cache, and returns product details. | High | Auth Service, Redis |
| **INV-301** | Inventory Service | As a Store Manager, I want to add stock quantities to a store or warehouse so that inventory levels are kept up to date. | • Stock addition must log a stock transaction history record with user ID and timestamp.<br>• Publishes a `STOCK_UPDATED` event to Kafka upon successful stock addition. | High | Auth Service, Product Service |
| **INV-302** | Inventory Service | As a System, I want to automatically deduct inventory after an order is successfully created so that we prevent overselling and keep stock levels consistent. | • Consumes the `ORDER_CREATED` event from Kafka.<br>• Subtracts ordered quantities from the corresponding store's inventory atomically.<br>• Implements optimistic locking / row versioning to handle concurrent billing counters. | High | Billing Service, Kafka |
| **INV-303** | Inventory Service | As a Store Manager, I want to transfer stock from one store/warehouse to another so that inventory is optimized across branches. | • Deducts stock from source and adds to destination in a single database transaction.<br>• Logs transaction audit details including source, destination, and transfer quantity. | Medium | Auth Service |
| **INV-304** | Inventory Service | As a Store Manager, I want to be alerted when stock level of a product drops below a defined threshold so that I can reorder it in time. | • System checks current stock against product-specific low-stock threshold during deduction.<br>• Publishes a `LOW_STOCK_ALERT` event to Kafka if inventory falls below the threshold. | Medium | Kafka |
| **BILL-401** | Billing Service | As a Cashier, I want to scan products and build a checkout cart so that I can prepare the customer's purchase details. | • Cashier scans barcodes to append products to the active bill session.<br>• System dynamically calculates running subtotal, individual GST amounts, and final grand total. | High | Product Service |
| **BILL-402** | Billing Service | As a Cashier, I want to process the payment and complete the checkout so that the order is finalized and records are saved. | • Supports multiple payment methods (Cash, UPI, Card).<br>• Creates order with status `CREATED` and publishes `ORDER_CREATED` event to Kafka.<br>• Marks payment status as `COMPLETED` and logs transaction details. | High | Kafka |
| **BILL-403** | Billing Service | As a Cashier / Customer, I want to generate a GST-compliant invoice PDF so that the customer has a valid proof of purchase. | • Generates a professional PDF detailing store information, tax invoice number, date, line items with GST breakdown, and final totals.<br>• PDF is archived and accessible via secure URL. | High | - |
| **NOTIF-501** | Notification Service | As a Store Manager, I want to receive an email or SMS alert for low-stock items so that I can place purchase orders without delay. | • Consumes the `LOW_STOCK_ALERT` Kafka event.<br>• Automatically generates and sends SMS/email notification containing low-stock details to the configured manager's address. | Medium | Inventory Service, Kafka |
| **NOTIF-502** | Notification Service | As a Customer, I want to receive a digital copy of my invoice on my phone or email so that I don't need a printed paper copy. | • Consumes the `ORDER_CREATED` event.<br>• Dispatches a beautifully formatted email/SMS with invoice receipt details and a download link to the PDF. | Low | Billing Service, Kafka |
| **ANALYTICS-601** | Analytics Service | As an Admin / Business Owner, I want to view a real-time sales dashboard showing revenue, tax collected, and top products so that I can monitor business performance. | • Consumes `ORDER_CREATED` events to increment daily revenue, store-wise sales, and product performance analytics.<br>• Dashboard metrics are cached in Redis to guarantee response times under 300ms. | High | Billing Service, Kafka, Redis |
| **ANALYTICS-602** | Analytics Service | As an Admin, I want to generate and export tax and GST reports so that I can submit accurate filings to tax authorities. | • Generates aggregated reports of CGST, SGST, and total taxes collected grouped by product category and date range.<br>• Supports exporting data to CSV format. | Medium | - |
| **GATEWAY-701** | API Gateway | As a System Administrator, I want all external client traffic routed through a single API Gateway so that we have centralized security, rate limiting, and routing. | • Routes paths to respective microservices: `/auth/**`, `/products/**`, `/inventory/**`, `/orders/**`, `/analytics/**`.<br>• Intercepts requests to validate Keycloak JWT tokens before routing.<br>• Applies Redis-based rate limiting to prevent API abuse. | High | Redis |
| **DIST-801** | Infrastructure | As a System, I want to use the Saga Pattern to orchestrate order processing and stock reservation so that distributed data consistency is maintained. | • If inventory reservation succeeds, proceed to checkout/payment.<br>• If inventory reservation fails (out of stock/insufficient quantity), trigger compensating transaction to set order status to `CANCELLED` and roll back any payment attempts. | High | Billing Service, Inventory Service, Kafka |
